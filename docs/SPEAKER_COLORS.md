# 말씀 화자별 색상 유지 작업 규칙

## 유지할 동작
하나님 말씀은 금색(god), 성령님 말씀은 초록(spirit), 성자 말씀은 분홍(son),
선생님 말씀은 보라(teacher), 예수님 말씀은 파랑(jesus)으로 인용 구간에 표시한다.
단순히 이름이 나왔다는 이유로 주변 문장 전체를 해당 화자의 말씀으로 지정하지 않는다.
직접 칠한 사용자 하이라이트가 겹치면 사용자 표시를 우선한다.

## 원고 데이터
- 일반 문단은 줄 배열이다. 빈 줄은 문단 경계이며 줄바꿈을 합치거나 바꾸지 않는다.
- 화자를 명시한 문단은 `{"p":["첫 줄","둘째 줄"],"sp":["god",null,"teacher"]}` 형식이다.
- 기존 sp 배열은 문단의 “…” 인용문 등장 순서와 일치해야 한다. 다른 인용부호가 앞에 있어도 기존 순서를 바꾸지 않는다. null은 의도적으로 색칠하지 않는 인용이다.
- 현재 뷰어는 “…” / "…" / ‘…’ 인용을 지원한다. 줄을 가로지르는 인용도 하나로 센다.
- 문단 줄들을 구분자 없이 이어붙인 글자 위치를 색상과 사용자 하이라이트가 함께 사용한다.
- 기존 p/sp 정보를 원고 재등록·변환·교체 때 삭제하지 않는다. 교체 전후를 비교한다.
- 화자가 분명하지 않거나 앞 문단에만 명시된 경우에는 문맥을 검토해 sp로 기록한다.
  화자 추측으로 잘못 색칠하지 않는다.

## 일반 배열로 가져온 새 원고
HWP 가져오기 도구는 일반 줄 배열을 만든다. sp가 없으면 뷰어의 inferSpeaker가
인용 앞의 “하나님께서/성령님은/성자는/선생은 …” 또는 뒤의
“라고 하나님께서 말씀하셨다” 같은 명확한 표현을 확인해 색칠한다.
화자가 명시되지 않으면 자동 지정하지 않는다.
speakerRanges와 buildLegend는 같은 판정 결과를 사용한다.
자동 표시가 없는 인용은 원고를 검토하고 필요한 sp를 넣는다.

## 변경·등록 때 반드시 확인
1. 시작할 때 두 저장소 main과 AGENTS.md를 최신 상태로 읽는다.
2. 화면 파일 `sayeon/malsseum/index.html`과 `malsseum/index.html`을 동일하게 유지한다.
3. 기존 sp 메타데이터를 보존하고, 새 편의 인용 화자 누락을 검토한다.
4. 다섯 화자, 세 인용부호, 여러 줄 인용, null, 수동 하이라이트 겹침을 확인한다.
5. 문법 검사(node --check)를 통과시킨다. 인용 색과 범례가 함께 보이는지 확인한다.
6. 제목·회독·듣기 한 줄 배치, 검색, 저장칸, 음성 문단 동기화가 유지되는지 확인한다.
7. 두 저장소에 커밋·푸시하고 Pages 성공 및 실제 배포 파일을 확인한다.
8. UPDATE_HISTORY.md에 원인·수정 내용·검증 결과를 남긴다.

## 경로 유지
앱 화면은 /sayeon/malsseum/, 원고는 /malsseum/malsseum.json.enc,
음성·시간표는 /malsseum/audio/이다. PWA 범위는 /sayeon/을 유지한다.

## 2026-10-04 확인한 누락 조건과 복구
기존 색상 CSS와 sp 렌더링 코드는 남아 있었다. HWP 가져오기 도구에는 sp 생성이 없고,
뷰어는 sp가 있는 문단의 “…”만 처리했으므로 일반 배열로 추가된 원고는 색상이 표시되지 않았다.
일반 배열의 명확한 화자 인용을 보완하고, 범례도 실제 표시 구간에서 생성하도록 수정했다.
